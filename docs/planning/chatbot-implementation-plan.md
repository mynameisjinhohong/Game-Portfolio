# 홍진호 소개 챗봇 구현 계획

## 1. 챗봇의 목적

포트폴리오 사이트 방문자(면접관, 인사담당자, 실무자)가 홍진호에 대해 궁금한 점을 자연어로 질문하면, 관련된 경험·프로젝트·기술·강점을 즉시 답변해주는 기능이다.  
단순한 장식이 아니라 포트폴리오 탐색 경험을 실질적으로 보조하는 역할을 한다.

---

## 2. 사용자 질문 유형 및 답변 범위

### 2-1. 지원하는 질문 유형

| 유형 | 예시 질문 |
|------|-----------|
| 자기소개 | "홍진호는 어떤 개발자인가요?" |
| 기술 스택 | "주로 어떤 언어와 엔진을 사용하나요?" |
| 프로젝트 | "어떤 게임을 만들었나요?", "대표 프로젝트를 소개해주세요" |
| 역할 및 기여 | "팀 프로젝트에서 어떤 역할을 맡았나요?" |
| 강점/차별점 | "가장 잘하는 분야가 무엇인가요?" |
| 배운 점 | "프로젝트를 통해 무엇을 배웠나요?" |
| 연락처/채용 | "포트폴리오나 이력서는 어디서 볼 수 있나요?" |

### 2-2. 답변 범위 (In-scope)

- 홍진호의 경력, 학력, 주요 기술 스택
- 제작한 게임 목록, 각 게임의 역할·기술·배운 점
- 강점, 작업 스타일, 협업 경험
- Itch.io 링크 등 외부 링크 안내

### 2-3. 답변 범위 (Out-of-scope)

- 홍진호와 무관한 일반 지식 질문
- 개인 연락처, 주소 등 민감 정보
- 실시간 정보 조회(날씨, 뉴스 등)

## 3. 로컬 LLM 우선 검토 방향

### 3-1. 배경

맥미니 환경을 활용해 외부 API 비용 없이 로컬에서 LLM을 구동하는 방향을 우선 검토한다.

### 3-2. 검토 대상 스택

| 항목 | 후보 |
|------|------|
| 런타임 | [Ollama](https://ollama.com/) |
| 모델 | Llama 3.2 3B / Gemma 3 4B (경량, 맥미니 적합) |
| 프레임워크 | LangChain.js 또는 직접 HTTP 호출 |
| RAG 벡터 DB | ChromaDB (로컬), 또는 단순 JSON 파일 기반 |

### 3-3. 로컬 LLM 준비 작업

1. Ollama 설치 및 모델 다운로드 확인
2. 맥미니 RAM/성능 기준 적합 모델 선정
3. 포트폴리오 데이터(JSON/Markdown) 임베딩 파이프라인 구성
4. API 엔드포인트 노출 방식 결정 (로컬 서버 → 프론트 연동)

### 3-4. 폴백 전략

로컬 LLM 품질이 요구 수준에 미달할 경우 (추가 비용 없는 방법):
- 더 나은 경량 오픈소스 모델로 교체 (예: Mistral 7B, Phi-3 mini)
- 시스템 프롬프트 및 FAQ 데이터 보완으로 답변 품질 향상
- 답변 길이 제한 및 컨텍스트 최적화로 품질·속도 균형 조정
- 정형화된 FAQ 기반 규칙형 응답을 보조 수단으로 병행

## 4. 챗봇 데이터 소스

### 4-1. 포트폴리오 컨텍스트 데이터

- `docs/data/portfolio-context.md` (또는 JSON): 홍진호 기본 정보, 기술 스택, 경력
- `docs/data/games.json`: 각 게임별 제목, 역할, 사용 기술, 배운 점, Itch.io 링크
- `docs/data/faq.md`: 자주 예상되는 질문-답변 쌍 (프롬프트 품질 보조)

### 4-2. 컨텍스트 주입 방식

RAG(Retrieval-Augmented Generation) 또는 단순 시스템 프롬프트 삽입 방식 중 선택:
- **RAG**: 질문과 유사한 문서 청크를 벡터 검색 후 컨텍스트로 주입
- **시스템 프롬프트 삽입**: 전체 포트폴리오 정보를 시스템 프롬프트에 포함 (데이터 규모가 작을 때 적합)

초기에는 시스템 프롬프트 삽입 방식으로 시작하고, 데이터가 늘어나면 RAG로 전환한다.

## 5. 기본 UX 흐름

```
방문자 → 사이트 우하단 채팅 버튼 클릭
      → 챗봇 패널 열림
      → 환영 메시지 + 예시 질문 버튼 표시
      → 질문 입력 또는 예시 버튼 클릭
      → 로딩 인디케이터 표시
      → 답변 스트리밍 출력
      → 대화 이어가기 가능
```

### 5-1. UI 요소

- 플로팅 채팅 버튼 (우하단 고정)
- 채팅 패널 (슬라이드업 또는 사이드 드로어)
- 예시 질문 칩: "어떤 게임을 만들었나요?", "주요 기술은?", "연락 방법은?"
- 메시지 버블 (사용자 / 챗봇 구분)
- 스트리밍 타이핑 효과

## 6. 맥미니 설치 작업 분류: 사람 vs 에이전트

로컬 LLM을 맥미니에 설치·구성하는 과정은 일부 작업이 물리적 접근이나 권한 확인을 요구하므로, 아래와 같이 역할을 나눈다.

### 6-1. 사람이 직접 수행해야 하는 작업

| 작업 | 이유 |
|------|------|
| Ollama 공식 사이트에서 macOS 설치 패키지 다운로드 및 실행 | GUI 설치 마법사, macOS 보안 승인 팝업 필요 |
| 맥미니에서 `ollama pull <모델명>` 실행 및 모델 다운로드 확인 | 터미널 직접 접근 필요, 대용량 다운로드 중 상태 확인 |
| macOS 시스템 환경설정 → 개인 정보 보호에서 Ollama 접근 권한 허용 | OS 수준 권한 다이얼로그는 자동화 불가 |
| 맥미니 RAM 및 CPU 사양 확인 후 적합 모델 결정 | 실제 하드웨어 스펙 파악 및 판단 필요 |
| 방화벽/네트워크 설정에서 외부 접근 허용 여부 결정 | 보안 정책 판단은 사람이 해야 함 |
| Ollama 서버가 외부(배포 환경)에서 접근 가능하도록 공인 IP 또는 터널 설정 | 네트워크 환경(공유기, ISP)에 따라 수동 설정 필요 |

### 6-2. 에이전트(Claude Code)가 자동으로 수행할 수 있는 작업

| 작업 | 방법 |
|------|------|
| 포트폴리오 컨텍스트 데이터 파일(`portfolio-context.md`, `games.json`) 작성 | 파일 생성 및 편집 |
| 시스템 프롬프트 템플릿 작성 및 튜닝 | 파일 작성 |
| 백엔드 API 엔드포인트 코드 구현 (Ollama HTTP 호출 포함) | 코드 생성 |
| 프론트엔드 채팅 UI 컴포넌트 코드 구현 | 코드 생성 |
| Ollama가 이미 실행 중인 환경에서 `curl` 등으로 API 동작 검증 스크립트 작성 | 스크립트 작성 |
| FAQ 기반 규칙형 응답 보조 모듈 구현 (비용 없는 폴백) | 코드 생성 |
| 답변 품질 테스트 케이스 및 FAQ 데이터 파일 작성 | 파일 작성 |
| 환경 변수 파일(`.env.example`) 및 실행 가이드 문서 작성 | 파일 작성 |

### 6-3. 요약

> 에이전트는 **코드와 데이터 파일**을 모두 준비할 수 있다.  
> 단, **Ollama 설치·모델 다운로드·OS 권한 설정**은 맥미니에 직접 접근할 수 있는 사람이 먼저 완료해야 에이전트의 연동 작업이 의미를 가진다.  
> 따라서 권장 순서는: **사람이 Ollama 설치 및 모델 준비 → 에이전트가 나머지 코드·문서 작업 진행** 이다.

## 7. 후속 구현 작업 분해

| 우선순위 | 작업 | 규모 |

| 5 | 시스템 프롬프트 작성 및 답변 품질 튜닝 | Small |
| 6 | 배포 환경에서 로컬 LLM 연동 및 모델 품질 검증 | Medium |
| 7 | 답변 품질 테스트 및 FAQ 데이터 보완 | Small |

## 8. 기술 제약 및 리스크

| 리스크 | 완화 방안 |
|--------|-----------|
| 맥미니 성능 부족으로 LLM 응답 느림 | 경량 모델 선택, 응답 길이 제한 |
| 로컬 LLM 답변 품질 부족 | 더 나은 오픈소스 모델로 교체, FAQ 데이터 및 시스템 프롬프트 보완 |
| 배포 환경에서 로컬 LLM 미노출 | 클라우드 배포 시 API 전환 또는 별도 서버 구성 검토 |
| 포트폴리오 데이터 업데이트 누락 | 데이터 파일 단일화, 챗봇과 사이트 콘텐츠 동기화 유지 |
